# 需求规格说明

## 1. 用户角色

1. 报销用户：上传发票图片，查看识别和校验结果，确认报销表单。
2. 课程验收者：查看公开真实发票样例、页面截图、功能验证结果和重复报销拦截效果。

## 2. 已实现功能

### 2.1 Flask Web 页面

`src/invoice_app/app.py` 已实现服务端渲染上传页面、处理结果页和提交接口。支持 PNG、JPG、JPEG、BMP 和 WEBP 图片。

### 2.2 QR 检测、裁剪与解码

真实模式适配器使用 Ultralytics YOLO 权重定位 QR 区域，选择最高置信度框并生成裁剪图。OpenCV QR 解码器只接收该裁剪图，不能直接解析整张发票图片，也不能作为 YOLO 检测的替代实现。

本次证据中的二维码来自公开真实电子发票样例 `evidence/real_samples/real_e_invoice.png`。原图二维码肉眼可见，临时 zxing-cpp 核验出的内容为：

```text
01,10,012001800311,33207675,46.62,20190508,76939056883466677916,E1BD,
```

### 2.3 OCR 与字段抽取

真实模式适配器使用 PaddleOCR 在隔离子进程中进行本地 GPU OCR，再调用 NVIDIA NIM 的 OpenAI 兼容在线 LLM API 抽取发票代码、号码、日期、购买方、销售方、金额、税额、价税合计和发票类型。默认接口地址为 `https://integrate.api.nvidia.com/v1`，默认模型为 `meta/llama-3.3-70b-instruct`。API Key 由运行者在本地环境变量中填写，不提交密钥。

当前本机已安装真实模式视觉依赖，已训练并放置 `runtime/models/yolo/best.pt`，并用公开真实发票样例完成 YOLO GPU、OpenCV 裁剪图解码、PaddleOCR GPU 子进程和 NVIDIA NIM 字段抽取验证。

### 2.4 校验、填单和去重

`validation.py` 已实现字段标准化、一致性校验和唯一键生成。`form_export.py` 已实现表单导出。`database.py` 使用 SQLite 保存记录，并通过标准化 `unique_key` 的唯一约束阻止重复报销。

### 2.5 页面证据

`evidence/screenshots/01_upload.png` 到 `12_duplicate_popup.png` 已基于公开真实发票样例重新生成，覆盖从上传到重复提交弹窗的完整流程。

## 3. 验收边界

本次验收看三个部分：公开真实发票样例和来源说明、页面运行结果与二维码核验、关键功能验证结果。真实模式适配器、预检脚本、YOLO 训练脚本和默认 YOLO 权重已经就绪；NVIDIA NIM API Key 仍只由运行者在本地 `.env` 中填写。临时 zxing-cpp 只用于证据核验，不作为系统运行时模块。

## 4. 数据要求

课程交付样例使用 MIT License 下的公开真实电子发票图片。模型训练和扩展测试可以按任务选择公开数据：QR 检测使用带二维码框的数据，中文 OCR 和字段抽取使用中文票据数据。这样更符合不同任务的标注差异。
