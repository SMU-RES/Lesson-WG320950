# 测试与验收方案

## 1. 本地验证方式

可运行以下命令检查本地样例链路和 Web 流程：

```bash
python -m pytest
python -m pytest tests/test_web.py
```

这些命令用于验证 Web 流程、流水线、校验、数据库、表单导出、严格真实模式接口约束和 NVIDIA NIM 配置默认值。真实模式验收需要确认 `cv2`、`paddleocr`、`paddle`、`ultralytics`、CUDA 可用 PyTorch、PaddlePaddle GPU、`runtime/models/yolo/best.pt` 和 NVIDIA NIM 密钥均已就绪；本地可通过 `scripts/check_real_mode.py` 做预检。

## 2. 已覆盖范围

`tests/*` 包含：

- `tests/test_pipeline.py`：完整流水线和裁剪图传递。
- `tests/test_llm_extractor.py`：NVIDIA NIM 默认接口、模型和密钥读取方式。
- `tests/test_yolo_detector.py`：YOLO 缺依赖、缺权重、最高置信度框选择和禁止 OpenCV 替代检测。
- `tests/test_qr_decoder.py`：OpenCV 解码器只读取 YOLO 裁剪图，并按真实发票二维码字段位置解析。
- `tests/test_paddle_ocr.py`：PaddleOCR GPU 子进程调用、超时/错误处理和输出展开。
- `tests/test_real_mode.py`：真实模式装配 YOLO、OpenCV、PaddleOCR 和 NVIDIA NIM，且不使用 sample 适配器。
- `tests/test_real_mode_scripts.py`：真实模式预检和 YOLO 训练脚本参数行为。
- `tests/test_validation.py`：字段标准化、校验和唯一键。
- `tests/test_database.py`：SQLite 写入和重复报销拦截。
- `tests/test_web.py`：Flask 上传、结果页、提交和异常处理。
- `tests/test_form_export.py`：报销表单导出。


`evidence/screenshots/01_upload.png` 到 `12_duplicate_popup.png` 已重新生成，验收时可按顺序查看上传、识别、校验、填单和重复拦截。

## 4. 必须保持的规则

1. QR 解码器只能接收裁剪图，不能接收整张发票图片。
2. 本地样例运行不能要求 `ultralytics`、`opencv-python`、`paddleocr` 或真实 LLM API Key。
3. 真实模式使用 Ultralytics YOLO 权重、OpenCV 裁剪图解码、PaddleOCR 本地 GPU OCR 子进程和 NVIDIA NIM 字段抽取接口；缺少任一依赖、权重或密钥时应明确失败，不能静默降级到 sample。
4. SQLite 必须按规范化唯一键阻止重复报销。
5. 临时 zxing-cpp 只记录为证据核验，不写进运行时链路。

## 5. 交付检查

```bash
python scripts/package_delivery.py --dry-run
```

该命令检查交付清单，不会创建 ZIP。

交付清单应只使用三个顶层目录：`code/`、`演示/`、`报告pdf版本/`。其中 `演示/` 收纳截图，`报告pdf版本/` 收纳 PDF 报告，`code/` 收纳项目代码和默认 YOLO 权重；真实密钥 `.env`、数据库、训练 runs 和非默认模型权重必须保持排除。
